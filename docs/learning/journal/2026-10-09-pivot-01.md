# Session 2026-10-09 — Pivot 01

## Context

Before any product code existed, the project was repositioned from a vertical SaaS for clinics (Aura Studio / Aura Flow) to an enterprise agentic automation platform (AURA / Aura Ops). Decision: `brain/decisions/0007-pivot-to-enterprise-agentic-automation.md`.

## Why the pivot happened

The project's real goals are an enterprise AI engineering lab and a portfolio aligned with corporate AI work. Accounts Payable exercises the hard parts of that work (rules vs AI, human approval, audit) better than a booking flow.

## What changed

- Positioning: README, COMPANY, ORGANIZATION, ROADMAP (now 11 stages, 0–10).
- New canonical docs: `docs/product/AURA-OPS.md`, `docs/architecture/README.md`, `docs/status/CURRENT.md`, `simulation/NEXA-GROUP.md`.
- `AGENTS.md`: deterministic-first, human approval for financial actions, status vocabulary, financial synthetic-data rule.
- Communication and glossary examples moved to the finance domain; six finance terms added.
- `tools/check_docs.py` now also checks the training level in `docs/status/CURRENT.md`.

## What remained

Training system and levels, memory routing, communication policy, pstack usage, session lifecycle, decisions 0001–0006 (0003 with an updated rationale).

## What I learned

- A pivot changes the *why* and the *what*, not the *how we work*: the process docs barely changed.
- Without Git, overwriting a document destroys history. The previous direction had to be written into the decision record by hand.
- Separating deterministic rules from AI is a design decision you make per workflow step, not per system.

## Corporate concepts introduced

Pivot, positioning, superseded decision, Accounts Payable, 3-way match, exception, SLA, audit trail, human-in-the-loop, segregation of duties.

## Technical implications

The first real code (Bootstrap 02) should be deterministic: data validation and matching rules, with tests. AI enters only at parsing and investigation, and only with evals.

## Portfolio implications

A reader now sees an enterprise AI engineering lab with an honest status table (only the docs system is implemented). Credibility depends on keeping that table accurate as code arrives.
