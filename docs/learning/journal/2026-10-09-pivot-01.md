# Sessão 2026-10-09 — Pivot 01

## Contexto

Antes de existir qualquer código de produto, o projeto foi reposicionado de um SaaS vertical para clínicas (Aura Studio / Aura Flow) para uma plataforma enterprise de automação agêntica (AURA / Aura Ops). Decisão: `brain/decisions/0007-pivot-to-enterprise-agentic-automation.md`.

## Por que o pivot aconteceu

Os objetivos reais do projeto são um laboratório de engenharia de IA enterprise e um portfólio alinhado ao trabalho corporativo com IA. Accounts Payable exercita as partes difíceis desse trabalho (regras vs IA, aprovação humana, auditoria) melhor do que um fluxo de agendamento.

## O que mudou

- Posicionamento: README, COMPANY, ORGANIZATION, ROADMAP (agora com 11 stages, 0–10).
- Novos docs canônicos: `docs/product/AURA-OPS.md`, `docs/architecture/README.md`, `docs/status/CURRENT.md`, `simulation/NEXA-GROUP.md`.
- `AGENTS.md`: determinístico primeiro, aprovação humana para ações financeiras, vocabulário de status, regra de dados sintéticos financeiros.
- Exemplos de comunicação e do glossário migrados para o domínio financeiro; seis termos de finanças adicionados.
- O `tools/check_docs.py` agora também verifica o nível de treinamento em `docs/status/CURRENT.md`.

## O que permaneceu

Sistema e níveis de treinamento, roteamento de memória, política de comunicação, uso do pstack, ciclo de vida da sessão, decisões 0001–0006 (0003 com justificativa atualizada).

## O que aprendi

- Um pivot muda o *porquê* e o *quê*, não o *como trabalhamos*: os docs de processo quase não mudaram.
- Sem Git, sobrescrever um documento destrói o histórico. A direção anterior teve que ser escrita à mão no registro de decisão.
- Separar regras determinísticas de IA é uma decisão de design tomada por etapa do workflow, não por sistema.

## Conceitos corporativos apresentados

Pivot, posicionamento, decisão substituída (superseded), Accounts Payable, 3-way match, exception, SLA, audit trail, human-in-the-loop, segregação de funções.

## Implicações técnicas

O primeiro código real (Bootstrap 02) deve ser determinístico: validação de dados e regras de matching, com testes. A IA entra apenas no parsing e na investigação, e somente com evals.

## Implicações para o portfólio

Um leitor agora vê um laboratório de engenharia de IA enterprise com uma tabela de status honesta (apenas o sistema de docs está implementado). A credibilidade depende de manter essa tabela precisa à medida que o código chegar.
